You now have a model big enough to memorise. That changes how its loss must be measured. The data is split: 90% to train on, 10% the model never trains on, called validation data. estimate_loss measures both.

  • Training loss says how well the model fits what it has seen.
  • Validation loss says how well it predicts text it has not seen, which is the only thing you care about.

Both fall together at first. When the training loss keeps falling and the validation loss flattens or rises, the model has started memorising its training text. That gap is overfitting, and the validation curve is where you read it.

Run the training script in the first experiment, then press Refresh. Every run you make is drawn here: solid for training, dashed for validation.

A caution about that last number. A loss of 0.36 per character would be extraordinary on ordinary English, where good character-level models score a little above 1. It is this low here because the incident threads are generated from a limited set of sentence patterns, so much of the validation text closely resembles training text. The model has learned the patterns well; it has not learned English. Keep that distinction: a loss tells you how well a model predicts this data, and how hard the data is matters as much as how good the model is.

That is the whole of a GPT. What separates this from a model you would give a real task is scale: thousands of times more parameters and millions of times more text. Session 5 puts the two side by side.
