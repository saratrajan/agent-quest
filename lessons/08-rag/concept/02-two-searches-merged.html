Session 7 measured two ways to search and found them level: shared words and embeddings each found a related incident in the top five about 92% of the time, and they fail on different queries. Production systems use both and merge the results, which is called hybrid search. That needs a proper keyword scorer and a way to merge.

BM25: keyword scoring done properly. Counting shared words treats every word alike. BM25, the standard since the 1990s, adds three corrections. For a query word t that appears f times in a document of length L:

score += idf(t) × f × (k₁ + 1) / ( f + k₁ × (1 − b + b × L / Lavg) )

idf(t) = ln( (N − n + 0.5) / (n + 0.5) + 1 )

  • Rare words count for more. N is the number of documents and n the number containing the word. "Refund" in 20 of 400 incidents is informative; "error" in 300 is not.
  • Repetition has diminishing returns. f appears on top and bottom, so the tenth mention adds far less than the first. k₁ (usually 1.5) sets how quickly it levels off.
  • Long documents are marked down. A long text contains more words by chance. b (usually 0.75) sets how strongly length is penalised.

Reciprocal rank fusion: merging without comparing scores. A BM25 score of 1.45 and a cosine of 0.87 are on unrelated scales, so they cannot be added. RRF ignores the scores and uses only positions. An item at rank r in a list earns 1 ÷ (k + r); its total across lists decides the merged order.

With two lists [a, b, c] and [b, c, d] and k = 60: b earns 1/62 + 1/61 = 0.0325, c earns 1/63 + 1/62 = 0.0320, a earns 1/61 = 0.0164 and d 1/63 = 0.0159. Merged: b, c, a, d. Being found by both searches beats being first in one. The constant k decides how much first place is worth; 60 is the conventional value and rarely needs changing.

Re-ranking: a second, slower opinion. The first search has to be fast because it looks at everything. A common refinement retrieves a generous shortlist cheaply, then asks a slower, more careful model to reorder just that shortlist. You will measure whether it helps here. It does not always.

Sources: Robertson and Zaragoza (2009), The Probabilistic Relevance Framework: BM25 and Beyond; Cormack, Clarke and Büttcher (2009), Reciprocal Rank Fusion Outperforms Condorcet and Individual Rank Learning Methods.
