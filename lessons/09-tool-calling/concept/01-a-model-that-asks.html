Retrieval gave the model evidence, but you chose the evidence: the same search, the same five incidents, every time. Some triage questions need a different lookup depending on what the ticket says. Was there a deploy just before this started? Who owns the service? What does the runbook say? The next step is to let the model decide what to look up. That is tool calling, and it is the mechanism underneath everything called an agent.

One fact removes most of the mystery: a language model cannot do anything except produce text. It does not run code, open connections or read databases. Tool calling is a convention layered on top of text:

  1. You tell the model which tools exist: a name, a description and the arguments, for each.
  2. When it would help, the model writes, instead of an answer, a small structured request: call this tool with these arguments.
  3. Your code notices the request, runs the real function, and adds the result to the conversation as one more message.
  4. The model is called again, now with the result in front of it, and either asks for another tool or answers.

Step through a real conversation, recorded on this Mac with the model you have been using. Watch who does what.

Three things to take from it.

  • The model only ever proposes. Every action in the world is carried out by code you wrote, which means every action can be checked, limited, logged or refused by code you wrote. Session 11 builds its guardrails on exactly this.
  • The description is the interface. The model has never seen your functions. All it knows is the text you supply, in a standard form called JSON Schema: 
    {"type": "function",
 "function": {"name": "get_service",
              "description": "Look up one service: owning team, tier, dependencies, runbooks.",
              "parameters": {"type": "object",
                             "properties": {"service_id": {"type": "string",
                                                           "description": "One of: search, payments, ..."}},
                             "required": ["service_id"]}}}
    A vague description produces wrong calls as surely as a vague prompt produces wrong answers.
  • A tool result is just more context. It lands in the same window as everything else and is read again on every later turn. The bars under the conversation show it: 559 tokens, then 772, then 943.

The request-and-result convention was popularised by Yao et al. (2022), ReAct: Synergizing Reasoning and Acting in Language Models, this session's reading.
