Byte-pair encoding builds the vocabulary from the data. Start with the 256 byte values. Find the pair of adjacent tokens that occurs most often, give that pair a new token number, and replace it everywhere. Repeat until the vocabulary is as large as you want.

The algorithm, stated exactly as your code will implement it:

  1. Let ids be the UTF-8 bytes of the training text, and next = 256.
  2. Count every adjacent pair (idsi, idsi+1).
  3. Take the pair with the highest count. If two pairs tie, take the one that appeared first. If the best count is below 2, stop.
  4. Replace each non-overlapping occurrence of that pair, left to right, with next. Record the merge and add 1 to next.
  5. Go to step 2 until next reaches the target vocabulary size.

Encoding new text replays the recorded merges in the order they were learned. Decoding expands each token back to its bytes. Because merges only ever join existing tokens, every token expands to a definite byte string and the round trip is exact.

Source: Sennrich, Haddow and Birch (2016), Neural Machine Translation of Rare Words with Subword Units. The idea began as a compression method: Gage (1994), A New Algorithm for Data Compression.
