Session 1 turned text into a list of token numbers. A language model's whole job is one function: given the tokens so far, give a score to every token in the vocabulary for "how likely is this one to come next". Those scores are called logits.

The simplest possible version looks only at the current token. That is a bigram model, and it is nothing more than a table with one row per token:

Current tokenscore for "a"score for "1"score for "R"…
P1.90.21.3…
I−0.8−1.10.1…
e0.3−2.0−1.4…

To predict what follows P, read off row P. In PyTorch that lookup is nn.Embedding(vocab, vocab): give it token numbers, get back their rows. An embedding is exactly this, a learned row of numbers per token. Here the row happens to be the scores themselves; from session 3 on the row will be a compact description of the token that later layers turn into scores.

In this session the tokens are single characters, so the vocabulary is the 77 distinct characters in the incident threads and the table has 77 × 77 = 5,929 numbers. Small enough to print and read.

The shapes you will meet in the code, for a batch of B windows of T tokens:

idx : (B, T) → logits : (B, T, V), where V is the vocabulary size

Every position in every window gets its own row of V scores, so one batch of 32 windows of 8 tokens makes 256 predictions at once.

The table starts as random numbers. Training is the process of changing them until row P really does say what tends to follow P in your tickets. The next two steps cover how the model is told it is wrong, and how it corrects itself.
